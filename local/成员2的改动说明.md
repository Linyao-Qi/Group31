# 成员2对已有代码的改动说明

本文档说明成员2在融合版本（version2）中对成员1、成员4代码所做的修改及原因。

---

## 对成员1代码的改动

### 1. `model/Job.java` — 新增两个字段

**改动：** 在 Job 模型中新增 `moId`（负责该岗位的 MO ID）和 `jobStatus`（岗位状态）两个字段，并添加对应 setter。原有 12 参数构造函数不变。

**原因：** MO 发布岗位时需要记录是谁发布的（moId），以便后续录用时进行权限校验（"这个 MO 只能操作自己发布的岗位"）。`jobs.csv` 中的预置岗位同样需要 moId 字段，才能让 MO 对预置岗位的申请也进行正常处理。

---

### 2. `data/JobDataLoader.java` — 重构为全 CSV 读写

**改动1：** CSV 解析时，支持可选第 13 列 moId 和第 14 列 jobStatus，向下兼容原有 12/13 列格式：
```java
if (parts.length >= 13 && !parts[12].isBlank()) job.setMoId(parts[12].trim());
if (parts.length >= 14 && !parts[13].isBlank()) job.setJobStatus(parts[13].trim());
```

**改动2：** 新增 `writeJobsToCSV(String path, List<Job> jobs)` 方法，将 Job 列表写入 CSV（14 列），含字段引号处理。

**改动3：** 删除原 `loadJobsFromDat` 方法（数据存储已统一为 CSV，DAT 相关方法不再需要）。

**原因：** 配合全项目 CSV 统一化改造，JobDataLoader 承担岗位数据的完整读写职责。

---

### 3. `data/jobs.csv` — 新增 moId 列，统一为职位总表

**改动1：** 在原有 12 列末尾追加 moId 列（第 13 列），J001/J002/J005 归属 MO001，J003/J004/J006 归属 MO002。

**改动2：** `jobs.csv` 升级为唯一职位数据源，MO 运行时发布的新岗位也直接追加写入本文件（原先写入独立的 `job.dat`/`job.csv`）。

**原因：** 单一数据源避免多处合并逻辑，架构更清晰。`MoService.acceptApplicant()` 权限校验也只需查一个文件。

---

### 4. `ui/TAJobsFrame.java` — 无需改动

**说明：** 原先存在"只加载 `jobs.csv`、看不到 MO 动态发布岗位"的问题，但由于岗位已统一写入 `jobs.csv`，该问题随架构调整自然消除，TAJobsFrame 无需修改。

---

## 对成员4代码的改动

### 1. `service/MoService.java` — 状态字符串统一

**改动：**
```java
// 原来
if (!"PENDING".equals(target.getAppStatus())) { ... }
target.setAppStatus("ACCEPTED");

// 修改后
if (!"Submitted".equals(target.getAppStatus())) { ... }
target.setAppStatus("Accepted");
```

**原因：** `ApplicationService.applyForJob()` 写入的状态是 `"Submitted"`，UI 层颜色渲染只识别 `"Accepted"`（首字母大写）。原来的全大写字符串导致 `acceptApplicant()` 始终报"只能处理待审核申请"，录用后状态也无法正确显示。

---

### 2. `service/MoService.java` — 去除双数据源合并，统一读写 `jobs.csv`

**改动：**
```java
// 原来同时搜索 job.dat + jobs.csv 两个来源
List<Job> allJobs = new ArrayList<>(FileUtil.read(JOB_FILE));
allJobs.addAll(JobDataLoader.loadJobsFromCSV(JOB_CSV));

// 修改后只读一个文件
List<Job> allJobs = JobDataLoader.loadJobsFromCSV(JOB_FILE); // JOB_FILE = "./data/jobs.csv"
```

**原因：** 岗位已统一写入 `jobs.csv`，不再需要合并多源。`publishJob` 也改为追加写入 `jobs.csv`。

---

### 3. `service/MoService.java` — 移除 `FileUtil` 依赖

**改动：** 所有 `FileUtil.read()` / `FileUtil.write()` 调用替换为 `JobDataLoader` 和 `ApplicationLoader` 的 CSV 方法。

**原因：** `FileUtil` 基于 Java 对象序列化（二进制 DAT 格式），全项目统一为 CSV 后该类已无用途，已删除。

---

### 4. `MoServiceTest.java` — 替换序列化写入为 CSV 写入

**改动：**
```java
// 原来
FileUtil.write("./data/app.dat", apps);

// 修改后
ApplicationLoader.writeApplicationsToCSV("./data/app.csv", apps);
```

**原因：** 数据存储统一为 CSV，测试数据的写入方式同步更新。

---

## 新增的数据层文件

### `data/CsvUtil.java`

提供全项目共用的 CSV 基础工具：
- `splitLine(String line)` — 带引号感知的字段分割
- `quoteField(String value)` — 字段加引号（null 安全，内嵌引号转义）
- `readAllLines(String path)` — 跳过表头读取数据行，文件不存在时自动创建
- `writeAllLines(String path, String header, List<String> lines)` — 写入表头和数据行

### `data/ApplicationLoader.java`

负责 `app.csv` 的读写，是新增的数据访问类：
- `loadApplicationsFromCSV(String path)` — 读取申请记录列表
- `writeApplicationsToCSV(String path, List<Application> apps)` — 写入申请记录列表

### 删除：`data/FileUtil.java`

原基于 Java 对象序列化的通用读写工具类，全项目 CSV 统一化后已无调用方，予以删除。
